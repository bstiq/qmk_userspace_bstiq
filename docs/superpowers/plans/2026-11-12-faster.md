## Current design (what the module does today)

### Wire protocol and buffers

`bk_split_flash_proto.h` — the control plane fits the 32 B RPC buffer:

```c
#define BKSF_PROTO_VERSION 2
#define BKSF_MSG_DATA_SIZE 20
typedef enum {
    BKSF_CMD_NONE = 0,
    BKSF_CMD_ARM,       // master -> slave: arm (invalidate boot2), reply ARMED
    BKSF_CMD_ARMED,     // slave -> master
    BKSF_CMD_BEGIN,     // master -> slave: image size in `value`, CRC in `data`
    BKSF_CMD_CHUNK,     // master -> slave: offset in `value`, `len` bytes in `data`, CRC32 in `crc`
    BKSF_CMD_ACK,       // slave -> master: ready / bytes received in `value`
    BKSF_CMD_NACK,      // slave -> master: refused/again
    BKSF_CMD_VERIFY,    // master -> slave: whole-image CRC in `value`
    BKSF_CMD_VERIFIED,  // slave -> master
    BKSF_CMD_SYNC,      // master -> slave: report durable bytes in `value` (ACK)
    BKSF_CMD_COMMIT,    // master -> slave: apply + reset
    BKSF_CMD_DONE,      // slave -> master (or abort ack)
    BKSF_CMD_ABORT,     // either: stop, stay recoverable
} bksf_cmd_t;

typedef struct __attribute__((packed)) {
    uint8_t  version; uint8_t cmd; uint8_t status; uint8_t len;
    uint32_t value;   // size / offset / CRC / flushed bytes
    uint32_t crc;     // BKSF_CMD_CHUNK: CRC32 over data[0..len-1]
    uint8_t  data[BKSF_MSG_DATA_SIZE];
} bksf_msg_t;
_Static_assert(sizeof(bksf_msg_t) == 32, "bksf_msg_t must be 32 bytes to fit the RPC buffer");
```

`bk_split_flash_pack.c` — the master sends a chunk in one transaction:

```c
bool bksf_bulk_send_chunk(uint32_t off, const uint8_t *data, uint8_t n, uint32_t *rxp_off_out) {
    bksf_bulk_frame_t frame = { .magic = BKSF_BULK_MAGIC, .offset = off, .len = n,
                                .crc = bksf_crc32(data, n) };
    memcpy(frame.data, data, n);
    bksf_bulk_ack_t ack = {0};
    bool ok = transport_execute_transaction(RPC_ID_BK_SPLIT_FLASH_CMD, &frame,
                                            BKSF_BULK_FRAME_SIZE, &ack, sizeof(ack));
    if (rxp_off_out) *rxp_off_out = ack.rxp_off;
    if (ok && ack.magic == BKSF_BULK_ACK_MAGIC && ack.status == BKSF_ST_OK) return true;
    if (ok && ack.magic == BKSF_BULK_ACK_MAGIC && ack.rxp_off == (uint32_t)(off + n)) return true; // already applied
    return false;
}
```

### Slave receive + single-buffer flush (the bottleneck)

`bk_split_flash_rpc.c` — receive state and accept:

```c
static bool     rxp_active;
static uint32_t rxp_staging, rxp_len, rxp_off, rxp_crc, rxp_crc_run, rxp_flushed;
static bool     rxp_pending;          // a full sector is buffered, awaiting flush
static uint32_t rxp_pending_off;
static uint32_t rxp_flush_not_before;

static bool bksf_rxp_accept(uint32_t off, uint8_t n, const uint8_t *data, uint32_t crc, uint8_t max_chunk) {
    if (!rxp_active || n == 0 || n > max_chunk || off != rxp_off || rxp_off + n > rxp_len || rxp_pending) {
        return false;                                    // <-- refuses while a sector is flushing
    }
    uint32_t in_sector = off & (BKSF_FLASH_SECTOR_SIZE - 1u);
    if (n > BKSF_FLASH_SECTOR_SIZE - in_sector) return false;   // never straddle a sector
    uint32_t got = bksf_crc32(data, n);
    if (got != crc) return false;                        // per-chunk CRC: NACK, do not advance
    uint8_t *buf = bksf_scratch();
    memcpy(buf + in_sector, data, n);
    rxp_crc_run = bksf_crc32_update(rxp_crc_run, data, n);
    rxp_off += n;
    if (in_sector + n == BKSF_FLASH_SECTOR_SIZE) {
        rxp_pending          = true;
        rxp_pending_off      = rxp_staging + (off - in_sector);
        rxp_flush_not_before = timer_read32() + BKSF_FLUSH_DELAY_MS;   // 4 ms
    }
    return true;
}
```

`bk_split_flash_flash.c` — one 4 KiB scratch and the erase+program flush:

```c
static uint8_t bksf_bounce[BKSF_FLASH_SECTOR_SIZE];   // the ONLY sector buffer
uint8_t *bksf_scratch(void) { return bksf_bounce; }

static bool __no_inline_not_in_flash_func(bksf_write_sector_ram)(uint32_t dst_off, bool verify) {
    flash_range_erase(dst_off, BKSF_FLASH_SECTOR_SIZE);     // <-- erase on every flush
    flash_range_program(dst_off, bksf_bounce, BKSF_FLASH_SECTOR_SIZE);
    if (!verify) return true;
    const volatile uint8_t *p = (const volatile uint8_t *)(uintptr_t)(BKSF_XIP_BASE + dst_off);
    for (uint32_t i = 0; i < BKSF_FLASH_SECTOR_SIZE; i++) if (p[i] != bksf_bounce[i]) return false;
    return true;
}

bool bksf_staging_flush_sector(uint32_t dst_off) {
    uint32_t irq = save_and_disable_interrupts();
    bool     ok  = bksf_write_sector_ram(dst_off, true);
    restore_interrupts(irq);
    return ok;
}
```

### Master pacing (serialized: send 4 KiB, wait for erase+program, repeat)

`bk_split_flash_rpc.c`:

```c
#define BKSF_RPC_MAX_TRIES 3

typedef enum {
    BKSF_SYNC_IDLE = 0, BKSF_SYNC_ARM, BKSF_SYNC_BEGIN, BKSF_SYNC_CHUNKS,
    BKSF_SYNC_RESYNC, BKSF_SYNC_FLUSH, BKSF_SYNC_VERIFY, BKSF_SYNC_COMMIT, BKSF_SYNC_REJOIN,
} bksf_sync_t;
```

```c

        uint32_t in_sector = up_off & (BKSF_FLASH_SECTOR_SIZE - 1u);

            return;

        up_fail_tries = 0;

    sync_tries++;
    if (bksf_rpc_send(BKSF_CMD_SYNC, 0, NULL, 0) && last_reply.cmd == BKSF_CMD_ACK &&
        last_reply.value >= up_flush_target) {
        if (up_off >= up_len) { sync_state = BKSF_SYNC_VERIFY; sync_tries = 0; return; }
        sync_state = BKSF_SYNC_CHUNKS; sync_deadline = timer_read32();

    sync_deadline = timer_read32() + BKSF_SECTOR_PACE_MS;
```

The slave reports progress through `SYNC`: `reply.value` = `rxp_flushed`,
`reply.data[0..3]` = `rxp_off` (used by `RESYNC` to tell "already applied" from
"retry").

### Fail-safe (must be preserved)

`bk_split_flash_flash.c` — ARM invalidates the boot2 CRC in place (no erase),
and COMMIT writes sectors 1..N then sector 0 (boot2 + vectors) last:

```c
bool bksf_arm(void) {
    static uint8_t page[BKSF_FLASH_PAGE_SIZE];
    memcpy(page, (const void *)(uintptr_t)BKSF_XIP_BASE, sizeof(page));
    memset(page + BKSF_BOOT2_CRC_OFFSET, 0, BKSF_BOOT2_CRC_SIZE);
    __compiler_memory_barrier();
    uint32_t irq = save_and_disable_interrupts();
    flash_range_program(0, page, sizeof(page));
    restore_interrupts(irq);
    return bksf_is_armed();
}

void __no_inline_not_in_flash_func(bksf_apply_and_reset)(const uint8_t *src, uint32_t len) {
    bksf_erase_eeprom();                                  // wipe wear-leveling first
    (void)save_and_disable_interrupts();                  // stays off for the whole copy
    for (uint32_t off = BKSF_FLASH_SECTOR_SIZE; ok && off < len; off += BKSF_FLASH_SECTOR_SIZE) {
        bksf_copy4k(bksf_bounce, src + off);
        ok = bksf_write_sector_ram(off, true);
    }
    if (ok) { bksf_copy4k(bksf_bounce, src); ok = bksf_write_sector_ram(0, true); }
    bksf_system_reset();                                  // never returns
}
```

## Why it is slow (root causes)

1. **Erase is interleaved with the transfer.** Every sector boundary goes to
   `BKSF_SYNC_FLUSH`, waits `BKSF_SECTOR_PACE_MS = 150` ms, then polls `SYNC`
   until the slave confirms. That is ~150 ms+ of dead time per 4 KiB of a
   ~150 KB image (~38 stalls).
2. **The receiver refuses chunks while a sector flushes.** `bksf_rxp_accept()`
   returns false when `rxp_pending` is set, and there is a **single** 4 KiB
   scratch (`bksf_bounce`). So the stream is strictly: send 4 KiB → wait for
   erase+program → repeat. No overlap.
3. **Conservative master pacing.** `BKSF_CHUNKS_PER_TICK = 4`,
   `BKSF_CHUNK_PACE_MS = 2`, `BKSF_SECTOR_PACE_MS = 150`.
4. **Slow-link assumption.** The module targets the QMK default
   `SERIAL_USART_SPEED` (the comment at `bk_split_flash_pack.h` says 230400,
   ~20945 B/s).

The wire format is *not* the problem: 224 B per single
`transport_execute_transaction` is efficient. Keep it.

## Reference design to borrow (from the svalboard firmware, reproduced here)

The svalboard implementation runs the same split link far faster and, more
importantly, **decouples the erase phase from the transfer phase**: the slave
erases the whole target region first, then the master streams pages with no
per-sector stall.

**1. The link runs at 1 Mbaud** (`keyboards/svalboard/config.h`):

```c
#define SERIAL_USART_SPEED 1000000
```

QMK's default when a board does not set it is `SELECT_SOFT_SERIAL_SPEED == 1`
→ `SERIAL_USART_SPEED 230400`
(`platforms/chibios/drivers/serial_usart.h:21-30`). So the reference link is
~4.3× faster.

**2. The slave erases the whole region up front, one sector per housekeeping
pass, gated so it can still answer the master** (`keyboards/svalboard/updater/update_split.c`):

```c
// One sector per housekeeping pass; a sector erase keeps interrupts off ~50 ms,
// longer than the master's serial timeout, so a sector that needs erasing waits
// for a request from the master since the last erase (gate: polled + gap).
static void slave_erase(uint32_t mseq, uint32_t off, bool gate) {
    if (!gate && !update_flash_sector_erased(off)) return;
    update_status_t st = update_flash_erase_sector(off);
    if (!post_begin(mseq, UPDATE_STATE_ERASING)) return;   // mailbox guard
    sl.polled = false;
    if (sl.erase_off == off) {
        if (st != UPDATE_OK) {
            slave_fail(st == UPDATE_UNAVAILABLE ? UPDATE_UNAVAILABLE : UPDATE_FLASH_ERR);
        } else {
            sl.erase_off += UPDATE_FLASH_SECTOR;
            if (sl.erase_off >= sl.erase_end) {
                usplit_pages_init(&sl.pages, sl.image_len);
                sl.state = UPDATE_STATE_RECEIVING;         // erase done -> accept pages
            }
        }
    }
    update_split_port_unlock();
}
```

The gate (in the slave's housekeeping) is:

```c
uint32_t erase_off  = sl.erase_off;
bool     erase_gate = sl.polled && (int32_t)(now - sl.rx_ms) >= SVAL_UPDATE_SPLIT_ERASE_GAP_MS; // 5 ms
// ... case UPDATE_STATE_ERASING: slave_erase(mseq, erase_off, erase_gate);
```

The manifest check computes the erase range, then hands off to `ERASING`:

```c
sl.image_len = SL_MANIFEST->image_len;
sl.erase_off = 0;
sl.erase_end = (sl.image_len + UPDATE_FLASH_SECTOR - 1) / UPDATE_FLASH_SECTOR * UPDATE_FLASH_SECTOR;
sl.state     = UPDATE_STATE_ERASING;
```

**3. The master waits for the erase to finish, then streams pages with the link
live** (`update_split.c`, the relay state machine): after the manifest is sent,
the master sits in `RELAY_ERASE_WAIT` polling `STATUS` every
`SVAL_UPDATE_RELAY_POLL_MS` (20 ms) until the slave reports `RECEIVING`, then
switches to `RELAY_PAGES` and streams; there is no per-sector wait during the
stream.

**4. The relay keeps the link pumped continuously** with a per-pass time budget:

```c
#define SVAL_UPDATE_RELAY_PASS_MS 4

void update_relay_task(void) {
    if (!update_relay_busy()) return;
    uint32_t t0 = update_split_port_now_ms();
    while (relay_step() && update_relay_busy() &&
           update_split_port_now_ms() - t0 < SVAL_UPDATE_RELAY_PASS_MS) {
    }   // as many RPCs as fit in 4 ms per housekeeping pass, back-to-back
}
```

Measured on that firmware: 125,696 B relayed in **11.1-11.4 s** (≈11 KB/s),
where the wire format is actually *less* efficient than yours (24 B payload over
QMK's multi-transaction RPC path). The speed comes from the fast link and the
erase/stream split, not from the frame.

## Required changes (in priority order)

Keep the per-chunk CRC32, the whole-image CRC `VERIFY`, and the
resync-after-lost-reply (`BKSF_SYNC_RESYNC`) behavior exactly.

### 1. Erase the whole staging region before any image bytes move

- Add a slave-driven erase phase started by `BKSF_CMD_BEGIN` (or a new
  `BKSF_CMD_ERASE`). Erase one 4 KiB sector per `housekeeping_task_bk_split_flash()`
  pass, using `flash_range_erase`, with interrupts toggled **per sector** (not
  held off across the whole region).
- Report progress through `SYNC`: while erasing, `reply.value` = bytes erased
  so far (or a distinct reply); when `rxp_erased == rxp_len`, the slave is ready
  for chunks.
- The master adds a wait state (e.g. `BKSF_SYNC_ERASING`) after `BEGIN`: poll
  `SYNC` until the whole window is erased, then enter `BKSF_SYNC_CHUNKS`.
- After this change, `bksf_write_sector_ram()`'s `flash_range_erase` is
  redundant for the staging path — the flush becomes **program-only** (~11 ms
  per sector instead of erase+program).

### 2. Stop blocking the stream on the flush

- Either **double-buffer**: make the scratch `uint8_t bksf_bounce[2][4096]`
  with a toggle index, and let `bksf_rxp_accept()` fill sector *N+1* while
  sector *N* is programmed in housekeeping; or
- Since the flush is now program-only, **lower `BKSF_SECTOR_PACE_MS`** to the
  measured program time (start at ~20 ms) and allow a small number of sectors
  to be in flight.
- Remove the `|| rxp_pending` early-return from `bksf_rxp_accept()` once the
  buffer is double-buffered; keep the sector-straddle and per-chunk CRC rules
  and the `rxp_off` semantics exactly (they back `RESYNC` and `SYNC`).

### 3. Retune the pacing from measurements

- Raise `BKSF_CHUNKS_PER_TICK`, shrink or remove `BKSF_CHUNK_PACE_MS`, and
  reduce `BKSF_SECTOR_PACE_MS` after measuring. Consider raising
  `BKSF_BULK_CHUNK` toward the transport limit (the frame must stay ≤ 255 B, see
  the `_Static_assert` in `bk_split_flash_pack.h`) if the wire, not the
  per-transaction turnaround, is the bottleneck.

### 4. Optional: raise the link speed

Add an opt-in define, default off, so the default build is unchanged:

```c
// config.h or a new bksf build define
#ifndef BKSF_SERIAL_SPEED
// leave QMK's default
#else
#    define SERIAL_USART_SPEED BKSF_SERIAL_SPEED
#endif
```

Document that both halves must use the same speed and that the cabling must
handle it (the reference board uses 1,000,000). Do not change the default
silently.

### 5. Protocol version

If you add or change a wire command (e.g. a dedicated erase op), bump
`BKSF_PROTO_VERSION` in `bk_split_flash_proto.h` and update the default in
`tools/gen_peer_image.py` (it parses `BKSF_PROTO_VERSION` from the header, so
verify it still finds it). Both halves run the same build.

## Constraints

- Do **not** change the fail-safe: `bksf_arm()` must still invalidate the boot2
  CRC before any app sector is touched, and an interrupted update must still
  land in `RPI-RP2`.
- Do **not** change `bksf_apply_and_reset()` semantics (EEPROM wipe, sectors
  1..N first, sector 0 last, reset).
- Keep the per-chunk CRC32, the whole-image CRC `VERIFY`, and NACK-and-retry;
  a corrupted chunk must never be written to staging.
- Keep the module building when `SPLIT_TRANSACTION_RPC` is undefined (the
  `#else` stubs at the bottom of `bk_split_flash_rpc.c` /
  `bk_split_flash_pack.c`).
- Do not touch the combined-UF2 / `post_rules.mk` path or
  `tools/make_combined_uf2.py`.

### What changed (module only, plus a keymap speed revert)

- `bk_split_flash_flash.c/.h`
  - Split the old `bksf_staging_flush_sector()` (erase+program+read-back, ~56 ms)
    into `bksf_staging_erase_sector()` (erase only, ~45 ms) and
    `bksf_staging_program_sector()` (program only + read-back, ~11 ms).
  - `bksf_staging_erase_sector()` **skips** a sector that already reads 0xFF, so a
    staging window that has never been written is erased for free.
  - `bksf_write_sector_ram()` now takes the source buffer (`bksf_bounce`), used by
    the app-copy paths (COMMIT / self-flash); unchanged behaviour.
  - Kept a legacy `bksf_staging_flush_sector()` for the benchmark path only.
- `bk_split_flash_rpc.c`
  - **Erase decoupled from the transfer.** `BKSF_CMD_BEGIN` now starts a slave
    erase phase: one 4 KiB staging sector erased per `housekeeping_task` pass,
    progress in `rxp_erased`, reported through `SYNC`. Chunks are refused until
    the whole window is erased. No new wire command; `SYNC` carries `rxp_erased`
    in `data[4..7]` alongside `rxp_off` in `data[0..3]`.
  - New master state `BKSF_SYNC_ERASING` waits out the erase phase, then streams.
  - **Program-only flush.** The per-sector flush is now
    `bksf_staging_program_sector()`; the sector is already erased.
  - Pacing retuned: `BKSF_CHUNKS_PER_TICK 4 -> 8`, `BKSF_CHUNK_PACE_MS 2 -> 1`,
    `BKSF_SECTOR_PACE_MS 60 -> 20`, `BKSF_FLUSH_RETRY_MS 20 -> 10`; added
    `BKSF_ERASE_POLL_MS 50`, `BKSF_ERASE_MAX_TRIES 600`; `sync_tries` widened to
    `uint16_t`.
  - `BKSF_LEGACY_FLUSH` (module `config.h`, default 0): restores the exact
    pre-speed-up behaviour (erase in the flush, 60 ms pace, 4 chunks/tick, 2 ms
    chunk pace) for on-board A/B measurement.
- `bk_split_flash_proto.h`: `BKSF_PROTO_VERSION 2 -> 3` (BEGIN/SYNC semantics).
- Keymap `.../4x6_4_procyon/keymaps/vendor/config.h`: link speed knob only
  (see the follow-up below; ended at `SERIAL_USART_SPEED 921600`).

### Follow-up — link speed raised to 921600

On request the link was raised from 460800 to **921600** (`SELECT_SOFT_SERIAL_SPEED`
tops out at 460800, so `SERIAL_USART_SPEED` is set directly). Only **one** test
image was rebuilt at that rate:

- `bksf_images/bksf_921600_update.uf2` — `BKSF_TEST_UPDATE_SLAVE`,
  `BKSF_LEGACY_FLUSH=0`, `SERIAL_USART_SPEED 921600`, same 96 KiB peer.

(The 460800 A/B set was removed. The build script `~/bksf_921600_image.sh` is
self-contained: it forces the speed in its own override block and prints the
effective `SERIAL_USART_SPEED`/`BKSF_TEST`/`BKSF_LEGACY_FLUSH` it compiled with.)

Speed ceilings, for reference: `SELECT_SOFT_SERIAL_SPEED` documents 460800 max;
the RP2040 PIO driver's register ceiling is `clk_sys/8` = 125 MHz/8 = **15.625
Mbaud** (`serial_vendor.c`: `div = clock_get_hz(clk_sys) / (8 * SERIAL_USART_SPEED)`,
`clkdiv` min 1.0); the practical half-duplex wall is **~1 Mbaud** because the shared
pin is driven high through the weak pull-ups by a 2 mA GPIO (`enter_rx_state()`)
and the PIO receiver samples once per bit with no oversampling. 921600 is a
reasonable "double"; 1.25-2 Mbaud is cable-dependent.

On-board test at 921600 (dilemma) failed: the slave→master bulk ack arrived zeroed
on most chunks (`bulk ... not acked ... magic=0x00000000`, then `resync ...
already applied`), so the master resyncs every chunk and crawls. That is the 240 B
frame at the edge of the cable rise time, not a logic error (the small SYNC RPC
still returns ok). Middleground rates were added that give an **exact PIO clock
divider** (no dither): **625000** (`div = 25.0`) and **781250** (`div = 20.0`).

Images now in `bksf_images/`:

- dilemma: `bksf_625000_update.uf2`, `bksf_781250_update.uf2` (plus the known-bad
  `bksf_921600_update.uf2`);
- charybdis 4x6 `splinktegrated_rev1`:
  `bksf_charybdis_{460800,625000,781250}_update.uf2` (peer is 90112 B / 22 sectors
  there).

The base keymap configs for both boards were set to `SERIAL_USART_SPEED 625000`
(best-guess safe middle); the build scripts override per image and print the
effective macros. The charybdis `splinktegrated_rev3` variant is **full-duplex**
(separate TX GP1 / RX GP12, `SERIAL_USART_FULL_DUPLEX`), so its ceiling differs —
not built; ask if needed.

### Deliberate omissions / deviations from the plan

- **Change 4 (raise link speed): not added to the module.** The module ships no
  `BKSF_SERIAL_SPEED`; the rate is set in the keymap and was raised to 921600 in
  the follow-up above.
- **Change 2 was implemented via the plan's own alternative**, not double
  buffering: the slave keeps a **single** 4 KiB scratch. A flash write must hold
  interrupts off (~45 ms erase / ~11 ms program on RP2040), so the slave is deaf
  during it on a half-duplex link. Overlapping the program with the inbound
  stream (double buffer) would drop in-flight bulk frames and force costly
  `RESYNC` backoffs, which measured worse than simply serialising the ~11 ms
  program per sector. `rxp_pending` therefore stays a gate.

### Expected effect (why it is bounded)

The transfer is wire-bound. Peer = **98304 B (24 sectors)**, proto 3. At 460800
with the 240 B bulk frame (~5.5 ms/frame) the wire alone is ~2.5-2.6 s, so the
wire is a hard floor.

- Baseline (legacy): wire + ~60 ms dead per sector ≈ 2.6 + 1.4-2.1 s.
- New: erase phase (free when the window reads 0xFF; ~45 ms/sector when it holds
  stale data) + wire + ~20 ms program-serialised dead per sector ≈ 2.9 s.
- The win is largest when the staging window is already erased (flash the plain
  app UF2; the `*_combined.uf2` pre-fills staging and forces the erase phase).
- At this link rate and image size, a perfect transfer is only ~1.55x the
  baseline, so the plan's ≥2x target is not reachable without raising the baud.
- At **921600** the wire halves to ~1.3 s, so the per-sector program dead time
  (~20 ms) and the erase phase become the dominant fixed costs; the 0xFF-skip
  matters more at the higher rate.
